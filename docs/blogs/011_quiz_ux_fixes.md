# 011: クイズUX改善 — 重複選択肢・リトライ・回答フィードバック・数値正規化

**日付:** 2026-03-27

## 概要

子供ユーザーからのフィードバックを受け、クイズ画面の複数のUX問題を一括修正。重複選択肢の表示バグ、複数回答フィードバックの視認性、Try Againの効率化、結果画面のナビゲーション追加、数値表記揺れによる誤判定修正、カード内スクロール問題を解消した。

## 実施内容

### 1. 重複選択肢テキストの自動番号付与

Oak APIからインポートしたマッチ問題で、同じテキストの選択肢が複数存在するケースがあった（例: `factor, product, factor`）。ユーザーからは「AとCが同じ"factor"で区別できない」と報告。

- **原因:** マッチ問題→MC変換時に全問題が同じoptions配列を共有
- **影響:** DB全体で87問が該当
- **修正:** `quiz.html`のJS側で重複テキスト検出し、自動的に番号付与 `factor (1)`, `product`, `factor (2)`
- **判断:** DB修正ではなく表示層で対応。元データの意味（同じ概念の複数出現）を保持しつつ視覚的に区別可能にした

### 2. 複数回答フィードバックの改善

複数正解問題で1つしか選択しなかった場合、採点後に3つとも緑で表示され「自分が選んだ正解」と「選ばなかった正解」の区別がつかなかった。

- **修正前:** 選択有無に関わらず正解はすべて緑(`.correct`)
- **修正後:** 3段階の視覚フィードバック
  - 緑: 選択した＋正解 → `.correct`
  - 赤: 選択した＋不正解 → `.wrong`
  - オレンジ + "Missed"タグ: 選択しなかった＋正解 → `.missed`（新規CSSクラス）
- ロック状態のマルチ回答表示も修正（複数選択が正しく反映されるように）

### 3. Try Againで不正解のみリトライ

従来のTry Againは全問題を再出題しており、正解済み問題をスキップボタンで1問ずつ飛ばす必要があった（10問中2問不正解でも10回操作が必要）。

- **結果画面:** 「Retry Incorrect (N)」ボタンに不正解の問題IDをURLパラメータで渡す
- **クイズ画面:** `?retry=id1,id2` パラメータで該当問題のみフィルタリング
- サイドバー・モバイルナビゲーションもJS側で動的に再構築
- 例: 10問中No.5,9が不正解 → リトライ時はNo.5→No.9の2問のみ出題

### 4. 結果画面にチャンク間ナビゲーション追加

結果画面に「Try Again」「Back to [Subject]」しかなく、次のレッスンに進むにはsubject画面まで戻る必要があった。

- 「Next Lesson」「Previous Lesson」ボタンを追加
- リンク先は `/child/section/{chunk_id}`（講義画面）で、いきなりクイズには飛ばない
- `child_learn.py`の結果ルートで `sort_order` ベースの前後チャンクを算出

### 5. 数値表記揺れによる自由回答の誤判定修正

「1 982 000」が正解の問題に「1982000」と回答すると不正解になっていた。

- **原因:** 完全一致チェックでスペース区切り数値と連続数値が不一致。文字数10未満でLLM採点もスキップ
- **修正:** `_normalize_number()` 関数を追加
  - スペース・カンマ・NBSPを除去
  - float変換で正規形に（`42` = `42.0`, `1.50` = `1.5`）
  - 完全一致チェックと代替回答チェックの両方に適用
- 対応パターン: `1982000` / `1,982,000` / `1 982 000` すべて同一とみなす

### 6. クイズカードのスクロール問題解消

問題文＋選択肢が長い場合、カード内にスクロールが発生して操作しづらかった。

- `max-height: calc(100vh - 160px)` 制限を削除
- `.choices`の`overflow-y: auto`を削除
- カードが自然な高さで表示され、ページ全体のスクロールに委ねる形に
- パディング・ギャップをコンパクト化して1画面に収まりやすくした

## 技術メモ

- 重複選択肢の検出はクライアントサイドで`O(n)`のテキスト出現回数カウント
- リトライモードはURLパラメータベースでサーバー側の変更なし（既存のクイズルートをそのまま利用）
- `_normalize_number`はre.subで前処理後float変換を試みる安全な実装（数値でない文字列はそのまま返す）

- `templates/child/quiz_result.html` — リトライボタン、prev/nextナビ
- `routes/child_learn.py` — prev/next chunk算出、incorrect_ids、数値正規化
